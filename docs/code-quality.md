# 代码质量与验收标准

本标准用于 Coding Rewind 的修复、评审与后续验收。每条都对应用户可观察的行为或现有架构约束，不以文件行数、抽象层数或测试数量评分。

## 参考依据

- [Maccy AppDelegate](https://github.com/p0deje/Maccy/blob/f0b571e32e4031d7b91ba811f50d0f33e8e5548b/Maccy/AppDelegate.swift) 集中持有状态栏对象，并将显示状态与偏好同步。借鉴其明确的状态所有权。
- [Maccy 设置](https://github.com/p0deje/Maccy/blob/f0b571e32e4031d7b91ba811f50d0f33e8e5548b/Maccy/Settings/GeneralSettingsPane.swift) 使用原生控件与分组。沿用原生响应链、快捷键录制和可访问标签。
- [KeyboardShortcuts 固定版本与本地补丁](../Vendor/KeyboardShortcuts/README.md) 把录制、注册结果和系统冲突处理留给专用组件。应用只组织自己的动作与反馈。
- [项目已核实的来源](sources.md) 定义 MIT 复用边界，SelectedTextKit 的选区捕获策略和 Memos 的服务契约继续沿用。

## 可判定的规则

| 标准 | 代码要求 | 验收证据 |
| --- | --- | --- |
| 用户能找到应用 | Dock 默认可见，设置可修改；菜单栏、应用菜单与浮窗进入同一个设置窗口；关闭窗口不退出后台服务 | 已安装包首次打开、关闭后重开、设置开关及重启读回，屏幕上确认图标 |
| 状态有唯一所有者 | 显示偏好只由一个模型保存及应用；同一动作的选项由共同协调器持有，视图和菜单不能各存一份；凭据沿用现有边界 | 偏好修改立即生效，重启保持，QA 数据与日常数据隔离；不同动作入口生成相同意图 |
| 配置不冒充结果 | 地址存在只能说明已配置；环境变量覆盖时明确来源；错误可见且保留草稿 | 非法地址、环境覆盖、离线反馈及恢复均从实际控件检查 |
| 副作用边界明确 | AppKit 负责窗口，Core 负责片段、队列和接聊；设置视图不直接发送片段或启动宿主命令 | 审查调用链，并运行受影响的行为回归 |
| 原文与请求不变质 | 首行元数据与正文分开，代码内空白不参与正文排版；离线队列按成功快照提交，过期刷新不能覆盖新卡；未知接聊结果不自动重发 | 混合选区代码原文、队列和刷新交错、sidecar 幂等与未知结果测试通过 |
| 凭据保持隔离 | Token 不进入 JSON、日志或公开证据；QA 不回退个人钥匙串；保留已安装开发启动器 | 静态门禁、隔离配置测试、交付包重启；涉及凭据机制时另验真实升级 |
| 测试证明行为 | 已复现故障留下可重放检查；改变可见行为时检查失败，内部重组不影响预期 | 失败基线与修复结果，不能用源码字符串匹配替代运行结果 |
| 改动易于接手 | 沿用已有模型和原生组件；移除死代码、叙述式注释与无依据兜底；新增依赖需有当前需求 | 独立 diff 审查，检查范围和剩余问题明确记录 |

## 验收顺序

1. 记录源码提交、工作区差异、系统版本及被测应用的二进制哈希。
2. 在隔离数据目录复现受影响行为，保留失败证据。临时进程由启动脚本负责超时退出与清理。
3. 运行 [scripts/check](../scripts/check)。静态检查、Swift、Python、扩展、脚本及图标规格全部通过。
4. 构建应用包，从 LaunchServices 打开。操作设置、菜单、快捷键及窗口，并读回磁盘配置和界面状态。
5. 安装交付包后再次核对图标、设置入口和重启。构建通过不能替代安装验收。
6. 更新 [开发进度](../progress/index.html)，分别记录实现、自动化验证、实机验收、合并与安装。

每项使用 `PASS`、`FAIL`、`BLOCKED`、`NOT_RUN` 或带理由的 `N/A`。系统权限未授权、尚未测过的聊天站点和未验证的云端部署都不能记为通过。私密日志与屏幕截图留在本机验收目录，不提交到公开仓库。

## 架构中的责任归属

| 责任 | 唯一落点 | 必须保留的边界 |
| --- | --- | --- |
| 窗口、菜单、快捷键生命周期 | `CodingRewindAppDelegate` 与专用 AppKit 控件 | Core 不导入 AppKit，设置视图不直接发送片段或执行宿主命令 |
| 卡片与共享动作状态 | `AppCoordinator` | 捕获、刷新、归档遵守同一提交规则；异步方法不能仅依赖 MainActor 推断没有交错 |
| 待发数据与重放提交 | `OfflineOutbox`；浏览器的串行后台队列 | 网络等待不持文件锁；只有持久化成功才能报告已入队 |
| 服务数据与分页 | Memos；各端现有网络适配器 | 页大小不是匹配记录总数；桌面热卡与云端待增强记录不得只查第一页 |
| 宿主请求与恢复 | `ConversationHandoffStore`、sidecar | 调用前落盘，未知结果不重发；安装目录作为显式跨进程输入 |
| 网页转换与云端定锚 | `extractors.mjs`、`enricher.py` | 仅规范化普通排版；选中代码保真，增强器只改顶部元数据 |

功能验收、源码审查、自动化回归、实际安装和云端部署分别记录在进度页。统一检查通过证明既有检查范围通过，不能替代未执行的实机路径，也不代表以后不再有缺陷。

已运行应用的 Dock 策略可用 `swift scripts/verify-app-presence.swift <PID> visible` 检查；隐藏模式将最后一个参数改为 `hidden`。该检查只证明系统激活策略，仍须在屏幕确认 Dock 图标与菜单栏图标。测试旧安装包时应能复现默认 Dock 不可见的失败。

## 2026-11-13 架构核验

本轮核验覆盖桌面、Core、宿主桥接、浏览器扩展与云端增强器。保留单实例 Memos、原生 AppKit 和既有队列，没有新增业务数据库、框架或依赖。

| 标准 | 本轮结论与证据 |
| --- | --- |
| 用户能找到应用 | 既有安装验收保持有效；本轮隔离包从 LaunchServices 启动并实测操作菜单，不代表日常安装已升级 |
| 状态有唯一所有者 | 修复 HUD 与菜单归档意图分离；真实菜单请求的 markSynthesized 从错误的 false 变为 true；新卡、缓存与过期刷新交错回归通过 |
| 配置不冒充结果 | 修复扩展 storage.set 拒绝仍返回 queued；持久化失败返回 error，成功入队正例保持通过 |
| 副作用边界明确 | 既有模块边界保留；安装与校验共享 Hook 命令生成器，子进程实测写入指定目录 |
| 原文与请求不变质 | Chrome 同一真实混合 DOM 选区对照证实代码空行恢复；桌面与云端第二页记录回归通过，桌面后页失败不发布部分结果 |
| 凭据保持隔离 | 本轮未改凭据机制；QA 使用隔离目录与合成令牌，全仓静态门禁通过。日常升级与真实云端部署单列状态 |
| 测试证明行为 | 保留失败基线；修复后 Swift 48、扩展 24、增强器 10 项通过，统一检查全部通过 |
| 改动易于接手 | 状态、游标和错误处理落在现有所有者；重叠刷新选择放弃旧响应，下一次刷新读取远端，不引入额外协调层 |

上述结论是当前审查与执行范围内的符合性判断。日常安装、扩展重新加载、云端部署及独立复核的最新状态以进度页为准。
