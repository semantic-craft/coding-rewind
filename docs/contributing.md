# 贡献与 agent 协作

本仓库包含立项架构文档与 v0.1 纯 Swift 原生工程，已于 2026-11-11 经用户授权初始化 Git 并作为 MIT 公开仓库发布。本说明同时给人和 agent 看，位置放在 `docs/`，与 [GitHub 关于贡献指南的说明](https://docs.github.com/en/communities/setting-up-your-project-for-healthy-contributions/setting-guidelines-for-repository-contributors) 一致；当前不建立空的 `.github` 工作流。

入口见 [README.md](../README.md)。

## 现在允许做的事

- 修正文档中的事实、链接、日期、错字，以及决定 / 方向 / 建议 / 待决的标记错误。
- 在获得授权后，补充已阅读的新来源；新来源必须写入 [sources.md](sources.md)，包含链接、已读内容、读取日期（Asia/Shanghai）、许可证据或「未知 / 非开源」，并说明与本项目的关系。
- 把用户新的原话按日期追加到 [requirements.md](requirements.md)，不要覆盖旧原话。

## 现在默认不允许的事

除非用户另给明确授权，否则不要：

- 添加未经要求的复杂 CI、自动部署，或向公开仓库推送未脱敏数据。
- 执行强推（`git push --force`）覆盖公开共享分支。
- 覆盖已有文件中的用户内容而不先报告冲突。
- 在尚未正式初始化代码工程时提前生成空的源码树、包管理文件或许可文件（2026-11-11 用户已选定 **MIT License** 与 **macOS 原生 Swift** 技术底座，待开启 v0.1 代码实现时一并落盘 `LICENSE` 与工程结构）。
- 引入任何 GPL、AGPL、Commons Clause、无许可或商业闭源项目的代码（本项目已定为 MIT 开源，只允许在遵守版权声明的前提下参考或吸收兼容 MIT 的实现）。
- 在仓库中加入真实私密聊天、真实提示词、截图中的真实对话，或未脱敏的日志。
- 把建议或转述写成用户决定，或把尚未立项的「自动暂存」「相关时提示」直接做进实现。
- 在未指定的机器上创建「官方」目录，或用其他位置冒充 Helios 上的项目根。

官方本机工作目录为 Helios 上的 `~/Projects/coding-rewind/`，公开远端为 `https://github.com/semantic-craft/coding-rewind`。其他位置若有副本，只能当备份，不能替代主工作目录。

## 如何记录信息

1. 用户原话用引用块保存，并写上日期和出处（例如消息编号）。
2. 讨论转述要标明「转述，非逐字原话」。
3. 调研结论要能回溯到 [sources.md](sources.md) 里的具体链接。
4. 待决事项保持待决；需要用户选择时，列出问题，不要代选。

## 对 agent 的额外要求

- 先核目标路径是否已有同名或仅大小写不同的内容；有冲突就停止并报告，不要覆盖。
- 本轮以及后续仅文档变更时，不要为了「看起来完整」而生成空的源码树、包管理文件或许可文件。
- 不要为了推进 M2 及以后的里程碑而自行开始编码。
- 不要把其他未授权任务带进这个仓库。
- 向用户提问应通过原聊天中已授权的通道；不要在文档里用假想的用户答复填空。
